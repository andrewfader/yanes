# Code, sound catalogue, and benchmark review — 2026-09-26

This review covered the first-party DSP/CLAP implementation, parameter and preset tables,
editor and native backends, sample-bank loading, test harnesses, render/comparison tools,
and repository documentation. Context included this conversation, the repository's validation
notes, and available test logs. No separate transcript files were found. Third-party ymfm was
inspected where necessary to verify register and phase-accumulator behavior; it was not modified.

## Sound catalogue

There are now 59 selectable sources and 81 factory presets, plus Manual. The added Custom
wavetable source uses the existing drawable 32-sample, 4-bit table. Its table is always active;
the Custom wave override switch remains useful with other sources. All former source, preset,
and parameter IDs retain their meanings. Custom-wave state uses version 16 and migrates v8–v15.

The 27 appended presets comprise three custom-wave recipes, a Game Boy duty macro, and starting
recipes for all 23 previously uncovered sources. These include triangle/saw leads and basses,
VRC7 keys, AY/POKEY voices, noise percussion, and the console/computer channel stacks. Preset
tests now require every source to have a factory recipe, in addition to their loudness,
headroom, and recall checks. The strengthened SID bass preset from the preceding change remains.

## Corrections

- **FM pitch:** YM2612/OPNA had the wrong phase-denominator factor and sounded an octave low;
  OPM's key-code mapping was a semitone sharp. Absolute-frequency tests now cover all seven
  hardware-FM configurations at 440 Hz and 3520 Hz, including the highest OPL octave divider.
- **FM articulation and automation:** note-off no longer clears the voice signature and keys
  the chip back on. OPL pitch changes preserve key-off and its pitch registers. Mid-block FM
  automation now reaches the core at its event offset, with a block-partition equivalence test.
- **FM controls:** OPM AM/PM now programs channel sensitivity; OPL waveform selection and depth
  bits are enabled. Unsupported controls are dimmed. The VRC7 brightness, six-operator ratio/
  feedback, VRC6 pulse-duty, and AY-noise mode controls no longer appear effective when unused.
  Previously dimmed Game Boy and analog Shape controls are exposed.
- **Audio-thread work:** FM cores are allocated during activation, not on the first note.
  Steady-frequency notes reuse their pitch register settings. GUI parameter changes no longer
  directly reset or mutate the NES core concurrently with audio processing.
- **NES stack:** live pitch, CC7, note volume/pressure, envelopes, noise settings, and layers now
  reach its output instead of being computed and discarded. Neutral settings preserve the
  separate APU regression's result. Layer and CC7 behavior have audio regression tests.
- **Playback robustness:** reactivation clears old voices/effects; malformed note events,
  invalid ports, and non-finite expressions are rejected. Sequence indexing avoids integer
  overflow on long holds, extreme tempo/pitch values are bounded, and SID cutoff remains
  usable at low sample rates. Drum pitch controls now transpose kick and swept transients.
- **Sample/utility handling:** oversized bank files are rejected before allocating their entire
  contents; the DPCM converter rejects empty or oversized encodings. Invalid/decreasing
  register-script records report errors instead of silently losing writes or throwing.
- **Editor:** fast strokes fill intervening samples, the larger preset menu stays inside the
  window, UTF-8 ellipsis fitting keeps complete code points, and host-rejected queued GUI
  events are retried. Linux dialog teardown terminates and reaps its child rather than waiting
  for the user to dismiss it; the teardown regression requires no display.
- **Benchmark correctness:** every Yamaha register render must contain audio, and OPL tests use
  OPL register fixtures. Comparison tools reject non-finite audio/thresholds and silent complete
  renders. Constant-energy self-comparisons work. `rom-mix` rejects silence even without ffmpeg;
  `rom` still permits unused isolated channels. The NES generated-score gate requires neither
  a private ROM directory nor Furnace and rejects a deliberately wrong source.

## Compatibility and limits

Existing YM2612/OPNA patches now play an octave higher, and OPM patches a semitone lower,
than the erroneous earlier implementation. OPL waveforms and FM release behavior also change
where the old controls were ineffective. These are intentional audible corrections, not state
migration failures. Older parameter IDs and project state remain readable.

The Furnace suite covers 21 specific default voices at three pitches, not every shape or
preset. Its pitch metric folds octaves; the new FM tests independently check absolute pitch.
The generated NES score compares two local models and is not a ROM capture or a silicon oracle.

Native Windows/macOS builds and interactive DAW checks were not run in this Linux session.
The initial sandbox could not access X11; the follow-up below exercised the actual Linux
editor on the existing display. Optional real-ROM oracle lanes were not enrolled in this
build. Separate historical transcripts were unavailable.

## CPU measurements

1 and 16 active MIDI notes. This was a Release build on Linux x86_64, Intel Core i9-10850K

128 blocks after activation, note setup, and warm-up. Timings include the CLAP test harness;

## Follow-up: native UI and leak checks

The production Linux editor was rendered at 50%, 75%, 100%, and 125%, across all seven pages,
with its real artwork, fonts, menus, and relevance rules. Three window creation/destruction
cycles exercised resizing, show/hide, timer registration, backing-pixmap/font cleanup, and
waveform sample clicks delivered through the X11 event pump at every size. The native run
also passed AddressSanitizer/UndefinedBehaviorSanitizer with leak detection disabled.

This found and fixed a real reopen crash: Xft's display-close hook could release cached glyphs
after XRender's hook had already run, recreating stale Render display information. A separate
minimal Xft drawing program reproduced it without YANES. Registering XRender before Xft
ensures reverse-order shutdown releases glyphs first. Repeated editor reopening now passes
in the ordinary Release build as well as under instrumentation. The Hardware tab now fits
without clipping, and unsigned waveform levels 10–15 display in full instead of `+…`.

All 91 Release tests passed after the production fixes; the two frontend/UI tests passed
again after the final standalone-test cleanup change. This is native backend verification
using a test host, not a claim that every DAW embedding flow has been manually checked.

```sh
build/frontend_tests --display-review /tmp/yanes-native-review
```

LeakSanitizer remained blocked by machine tracing restrictions even outside the sandbox.
Valgrind 3.25.1, unpacked locally with matching loader debug symbols, provided an independent
check. Plugin smoke, state migration, sample banks, notes/all sources, all factory presets,
and UI logic tests each reported zero memory errors and zero definitely, indirectly, or
possibly lost allocations. No leak suppressions were used.

The native editor lifecycle also finished with **zero memory errors and zero lost allocations**
under Valgrind. Its standalone host calls `FcFini()` at process exit: without that cleanup,
fontconfig reported 512 directly and 87 indirectly lost bytes, identically in the independent
preview. YANES itself must not call this process-global finalizer because the DAW and other
plugins can share fontconfig. After test-host cleanup, 53,610 bytes remained reachable in
library caches; these were not lost allocations. This verifies the exercised paths, not an
unbounded-duration or every-host leak guarantee.

With Valgrind and matching loader symbols available, run:

```sh
valgrind --leak-check=full --errors-for-leak-kinds=definite,indirect,possible \
  --error-exitcode=99 build/frontend_tests --display-review /tmp/yanes-native-review
valgrind --leak-check=full --errors-for-leak-kinds=definite,indirect,possible \
  --error-exitcode=99 build/note_tests build/YANES.clap
```
